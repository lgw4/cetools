# Migration Requirements Quality Checklist: Parse Context Carrier

**Purpose**: Validate that the requirements governing this behavior-preserving
migration are complete, unambiguous, internally consistent, and measurable,
before `/speckit-tasks` turns them into work items.
**Created**: 2026-09-11
**Completed**: 2026-09-11
**Feature**: [spec.md](../spec.md)
**Focus**: behavior preservation; scope and boundary semantics; migration and
delivery discipline; counts, traceability, and measurability.
**Depth**: standard. **Audience**: the spec's author, pre-tasks.

**Note**: This custom checklist is generated by the `/speckit-checklist` command based on feature context and requirements.
**Review Ownership**: This checklist is a reviewer-owned requirements-quality review artifact. Mark an item `[x]` only when the reviewer determines the requirements-quality criterion is satisfied.
**Marker Semantics**: `[x]` means the criterion has been reviewed and satisfied for requirements quality. It does not mean implementation work is complete.

**Evaluation basis**: every item below was evaluated against spec.md as
amended on 2026-09-11, with the source-level counts re-derived from the tree at
`b33a1b3` rather than taken from the spec. Nineteen items were satisfied as
written; nineteen required a spec amendment, listed under *Resolutions* below.
No item was closed by narrowing what it asked.

## Requirement Completeness

- [x] CHK001 Is evidence required for the wordings the frozen corpora never name? FR-016 forbids editing the golden and contract corpora and SC-001 offers them as the proof of FR-014, but no requirement obliges the feature to cover `expected` strings those corpora do not exercise. [Gap, Spec §FR-014/FR-016/SC-001]
- [x] CHK002 Are requirements defined for what happens when a per-parser conversion produces a report difference? The assumptions section names "stop and reconsider" only for a sort-order failure, not for the general case. [Gap, Spec §Assumptions]
- [x] CHK003 Does the spec state whether this feature adds a `CHANGELOG.md` entry? The project requires one for every user-visible change and this feature's central claim is that nothing user-visible changes, yet no requirement resolves that explicitly. [Gap]
- [x] CHK004 Are the criteria for choosing a site's scope documented, or only the three answers? FR-005 and the assumptions name the three sub-file scopes but state no rule an implementer could apply to a site not on the list. [Completeness, Spec §FR-005, §Assumptions]
- [x] CHK005 Is restoration of the single-definition guard held by an acceptance criterion? FR-020 requires the relaxation be closed, but FR-022's four counts do not include it and no success criterion measures it. [Gap, Spec §FR-020/FR-022]
- [x] CHK006 Are requirements defined for an abandoned or partially merged migration, in which the relaxed guard outlives the branch? FR-020 states the relaxation is temporary but specifies no enforcement beyond the final commit's existence. [Gap, Edge Case, Spec §FR-020]
- [x] CHK007 Does FR-027's new suite cover the empty-parent case FR-003 singles out? FR-003 calls out the top-of-file empty location as the case that must not grow a leading dot, but FR-027's three named cases do not include it. [Gap, Spec §FR-003/FR-027]
- [x] CHK008 Are the required contents of the carrier contract complete? FR-024 names four things it must cover and omits the deliberately preserved anomalies the contract must also pin down. [Completeness, Spec §FR-024]
- [x] CHK009 Are non-functional requirements intentionally absent? No performance, memory, or import-time requirement is stated for allocating a carrier per descent step, and the spec does not record that absence as deliberate. [Gap]

**Correction (CHK026, CHK032).** The 102/29 pair this table originally recorded
as verified was not. It summed the five parsers to 102 and then took the rest of
`rules.py` — 31 constructions less the 2 in `parse_task_parameters` — as 29,
which counts `_class_effect_problems`' single problem out of the in-file figure
and into the cross-file one at once. FR-012a, added by CHK018/CHK034 in the same
pass, says that problem is in-file. Resolved by an `ast` walk over `rules.py`:
24 in `_validate`, 2 in `parse_task_parameters`, 1 each in `_unreadable`,
`_unlistable`, `_not_a_regular_file`, and `_compose`, and 1 in
`_class_effect_problems` — so 103 in-file and 28 cross-file. SC-006, FR-009,
FR-012, FR-012a, the plan, the contract, research R3, and data-model.md were
corrected together, and T083 now checks the figure against the finished tree
rather than leaving it asserted.

Three findings were fed back into [data-model.md](../data-model.md) as
conversion hazards: one further list-of-problems test that is *not* one of the
17 under SC-007's now-explicit definition, one emptiness test written with the
operands reversed so a grep misses it, and one of the fifteen idiom sites that
inlines a three-way conditional and so will not match a mechanical rewrite.
