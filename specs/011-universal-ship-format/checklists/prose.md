# Prose & Number Rules Checklist: Universal Ship Description Format

**Purpose**: Requirements-quality review gate for the grammar-and-number rules — validate that FR-022, FR-022a, FR-023, FR-024 and FR-025 are stated precisely enough to implement without guessing, and that every sentence's number agreement, list joining and figure formatting is decidable from the written requirements. These items test the *rules as written*, not the rendered output.
**Created**: 2026-07-24
**Feature**: [spec.md](../spec.md)

**Scope of review**: `spec.md` with `research.md` §C, `data-model.md` §5 and `contracts/description-format.md` as requirement sources. These five requirements carry the majority of the feature's edge cases, so they are reviewed as their own domain.

**Cross-check status (2026-07-24)**: All 34 items reviewed. **All 34 resolved** — 29 required a `spec.md` edit, made the same day; five were already answered by a composing rule or by the per-sentence contract. The five original requirements became eleven (FR-021a, FR-022b, FR-022c, FR-023a, FR-024a, FR-025a added). The most consequential finding was CHK024: FR-025 as written forbade scientific notation and trailing zeros but left binary floating-point artefacts renderable, so a cost summed from a dozen components could have printed `MCr29.771999999999998`. New FR-025a caps precision before stripping.

## Number Words — Boundary Definition

- [x] CHK001 Is the boundary between word and digit stated as an inclusive rule, so "ten" and "11" are unambiguous? [Clarity, Spec §FR-022] → **Fixed**: FR-022 now reads "as words from zero to ten and as digits above ten" — ten is inside the word band, eleven outside, with no gap.
- [x] CHK002 Is zero covered by the words-to-ten rule, given FR-022 says "one to ten" but the zero-cargo edge case renders "zero"? [Gap, Spec §FR-022, §Edge Cases] → **Fixed**: FR-022 covers zero explicitly, so the zero-cargo edge case is an instance of the rule rather than an exception to it.
- [x] CHK003 Is the list of "counts of things" in FR-022 exhaustive, or illustrative — and if illustrative, is the classification rule for an unlisted quantity stated? [Clarity, Spec §FR-022] → **Fixed**: new FR-022c states the three rules are a partition and their lists illustrative, with the classifying test given in words: a quantity that counts discrete things follows FR-022.
- [x] CHK004 Is the list of "measured and rated values" in FR-022a exhaustive, or illustrative? [Clarity, Spec §FR-022a] → **Fixed**: same FR-022c — a value the rules measure or rate follows FR-022a.
- [x] CHK005 Do FR-022 and FR-022a partition every number the paragraph can print, with no quantity falling in both lists or neither? [Consistency, Spec §FR-022, §FR-022a] → **Fixed**: FR-022c requires the three to classify every number the paragraph can print, with none falling under two of them or under none. That is the partition, stated as a requirement rather than left to inspection.
- [x] CHK006 Is tonnage classified consistently, given FR-022a lists it as always-digits while the zero-cargo edge case and the SRD both spell small tonnage as words? [Conflict, Spec §FR-022a] → **Fixed**: new FR-022b puts tonnage in running prose under the count rule and names the five places it appears. FR-022a keeps the hull displacement and the rated values. The spec's Clarifications record the amendment.
- [x] CHK007 Is the classification of a *fractional* quantity specified, so 1.3 tons and 6.2 tons are decidable under the tonnage rule? [Gap, Spec §FR-022a, §FR-025] → **Fixed**: FR-022b renders any fractional tonnage as digits, so 1.3 and 6.2 are decidable without a further rule.
- [x] CHK008 Are build weeks classified, given they are a count of things under FR-022 but always exceed ten in practice? [Clarity, Spec §FR-020, §FR-022] → **Resolved**: build weeks are a count of things and follow FR-022. The smallest tabulated build time is 28 weeks, so the word band is unreachable in practice and the two rules agree on every buildable ship — noted in research §C.
- [x] CHK009 Is the tech level classified explicitly, given it is a rated value printed in a heading rather than in a sentence? [Clarity, Spec §FR-001, §FR-022a] → **Fixed**: FR-022a names tech level in its list, so a heading value is classified by the same rule as a sentence value.

## Singular / Plural Agreement

- [x] CHK010 Does FR-023 cover verb agreement as well as noun agreement, given sentences beginning "There is" / "There are" and "…is carried" / "…are carried"? [Gap, Spec §FR-023] → **Fixed**: FR-023 now says agreement covers verbs as well as nouns, with the example that motivated it ("There is one stateroom" against "There are two staterooms").
- [x] CHK011 Is agreement specified for a sentence whose subject is a *list*, where the first clause's number differs from the total? [Gap, Spec §FR-023, §FR-010] → **Resolved**: correctly per-sentence detail: contracts/description-format.md §6 states that the quarters sentence takes "is" only when there is exactly one clause whose count is one. FR-023 supplies the governing rule.
- [x] CHK012 Does FR-023 address irregular plurals, given that "armory" → "armories" and "laboratory" → "laboratories" defeat a suffix rule? [Coverage, Spec §FR-023, §FR-030] → **Fixed**: FR-030 now requires the plural spelling on the row wherever the paragraph can state a count, giving the reason: the SRD's plurals are not uniformly regular.
- [x] CHK013 Is the source of each plural spelling specified — derived by rule, or carried as data alongside the singular? [Clarity, Spec §FR-023, §FR-031] → **Fixed**: FR-030 — carried as data alongside the singular, never derived. That is what makes SC-007 hold for a row like "armory".
- [x] CHK014 Is agreement specified for mass nouns that take no count at quantity one, such as "fuel scoops"? [Gap, Spec §FR-017, §FR-023] → **Resolved**: data-model §4 records the mechanism: a fitting's `name` column carries its indefinite article and "fuel scoops" is its own plural, so one rule (`count == 1` uses `name`) renders countable and mass nouns alike with no per-kind branch.
- [x] CHK015 Is the "crew of one: one pilot" edge case generalised into a rule, or stated only as that one example? [Clarity, Spec §Edge Cases, §FR-018] → **Fixed**: generalised by FR-022 (zero-to-ten as words) and FR-023 (agreement). "a crew of one: one pilot" now follows from the rules; the edge case is an instance, not the definition.
- [x] CHK016 Is indefinite-article selection ("a meson screen" vs "an armory") specified anywhere, given several sentences require an article? [Gap, Spec §FR-013, §FR-017] → **Fixed**: new FR-023a — the article agrees with the sound the following word begins with, with "an armory" and "a meson screen" as the worked examples.
- [x] CHK017 Is the article before a tonnage specified, given the SRD writes "Using an 800-ton hull" against "a 100-ton hull"? [Gap, Spec §FR-005] → **Fixed**: FR-023a's third example is "an 800-ton hull", which is the SRD's own spelling in the Destroyer; research §C gives the leading-digit rule and why a general number-to-words check is unnecessary over a bounded hull table.

## List Joining

- [x] CHK018 Does FR-024 define the one-item case, so a single-element list emits no stray "and"? [Gap, Spec §FR-024] → **Fixed**: FR-024 now defines the one-item case: it renders as that item alone.
- [x] CHK019 Does FR-024 define the empty-list case, or is it excluded by requiring the containing sentence be omitted? [Coverage, Spec §FR-024, §FR-021] → **Resolved**: an empty list never reaches FR-024 — FR-021 omits the containing sentence first. The two rules compose, so no empty-list case exists to define.
- [x] CHK020 Is the serial comma settled, given "commas and a final and" admits both "a, b, and c" and "a, b and c"? [Ambiguity, Spec §FR-024] → **Fixed**: FR-024 settles it: no comma before the final "and". Required because the SRD prints both forms in different vessels.
- [x] CHK021 Is FR-024 stated to apply to every list in the paragraph — drives, quarters, weapons, screens, armour types, armour options, special features, crew, passengers — or only where a sentence requirement repeats it? [Coverage, Spec §FR-024] → **Fixed**: new FR-024a opens with "Every list", so the rule is stated once and applies to drives, quarters, weapons, screens, armour types, armour options, special features, crew and passengers alike.
- [x] CHK022 Is list *order* specified for each list, given that determinism (FR-003) makes ordering a requirement rather than a detail? [Gap, Spec §FR-003, §FR-024] → **Fixed**: FR-024a requires every list be ordered from a stable source, and cites FR-003 as the reason — ordering is a determinism requirement, not a rendering detail.
- [x] CHK023 Is the ordering rule stated in terms of a stable source (design order, table order, first appearance) rather than left to the renderer? [Clarity, Spec §FR-003] → **Fixed**: FR-024a names the two admissible sources: the order the design records its components, or the order the rules data tabulates them.

## Figure Formatting

- [x] CHK024 Does FR-025 specify a maximum precision, or only that trailing zeros are stripped — so a value like 0.00125 has a defined rendering? [Gap, Spec §FR-025] → **Fixed**: new FR-025a caps precision at six decimal places *before* stripping, so a cost summed from a dozen floats prints MCr29.772 rather than MCr29.771999999999998. Six places sits below the smallest priced figure (a standard missile, MCr0.00125) and above any artefact. This was a real gap: FR-025 as written forbade scientific notation and trailing zeros but left binary floating-point artefacts renderable.
- [x] CHK025 Are thousands separators specified, given the SRD prints "MCr2,768.145" and "1,096 tons" but also "a 5000-ton hull"? [Gap, Spec §FR-025] → **Fixed**: FR-025 — costs carry thousands separators, tonnage does not. The SRD is consistent on costs and inconsistent on tonnage, so the simpler rule is taken for tonnage; research §C records the evidence.
- [x] CHK026 Is the "trailing dangling decimal point" prohibition in the edge cases restated as a requirement, or does it exist only as an edge case? [Traceability, Spec §Edge Cases, §FR-025] → **Fixed**: FR-025 now carries "and without a trailing decimal point" as a requirement, rather than leaving it in the edge cases.
- [x] CHK027 Does FR-025 cover every numeric field, or only "tonnage and cost" — specifically, is the sensor DM's formatting specified? [Coverage, Spec §FR-025, §FR-009] → **Fixed**: FR-009 governs the sensor DM directly: an explicit sign at every magnitude. FR-025 covers tonnage and cost, and FR-022a covers the remaining rated values, so every numeric field has a formatting rule.
- [x] CHK028 Is the explicit-sign rule for dice modifiers stated to include zero, so Basic Military renders a sign rather than a bare "0"? [Clarity, Spec §FR-009] → **Fixed**: FR-009 says "zero included", with "DM+0" as the worked example — the Basic Military case that a bare sign rule would get wrong.
- [x] CHK029 Is rounding specified for a derived figure that need not be a whole number, such as fuel-processor throughput or hangar capacity? [Gap, Spec §FR-017, §FR-014] → **Resolved**: no rounding rule is needed: both derived figures are exact products of stated values — fuel-processor throughput is tonnage times the SRD's 20, and hangar capacity is the tonnage the design records. FR-025a governs how they print.
- [x] CHK030 Is the requirement that formatting be locale-independent stated, given FR-003 forbids ambient state and decimal separators are locale-sensitive? [Gap, Spec §FR-003, §FR-025] → **Fixed**: FR-003 now names the host locale alongside seed and timestamp, and forbids ordering a list by iteration over an unordered collection — the two ambient inputs that could reach a rendered figure.

## Grammar Under Omission

- [x] CHK031 Does FR-021's "the paragraph MUST remain grammatical after omission" define grammaticality concretely enough to check — no doubled spaces, no dangling conjunction, no empty parentheses? [Measurability, Spec §FR-021] → **Fixed**: new FR-021a defines it as a checklist: no doubled space, no sentence fragment, no dangling comma or conjunction, no empty parentheses, and no zero-quantity clause except the three a requirement calls for.
- [x] CHK032 Is sentence separation specified (single space, no newline), so omission cannot leave a visible gap? [Gap, Spec §FR-001, §FR-021] → **Fixed**: new FR-001a — sentences separated by one space, never by a line break — so omission cannot leave a visible gap.
- [x] CHK033 Are requirements stated for the case where a *clause within* a sentence is omitted rather than the whole sentence — the armour clause, the maneuver clause, the "but has no weapons installed" clause? [Coverage, Spec §FR-021, §FR-016, §FR-006] → **Fixed**: FR-021 now reads "Sentences — and clauses within sentences —", which covers the armour clause, the maneuver clause and the no-weapons clause that the original wording did not.
- [x] CHK034 Is SC-001's "no placeholder text, no empty parentheses and no orphaned punctuation" traceable to the rules that prevent each, rather than standing alone as an assertion? [Traceability, Spec §SC-001, §FR-021] → **Fixed**: FR-021a enumerates the same failure modes SC-001 asserts, so the success criterion is now traceable to the rule that prevents each rather than standing alone.
